Why this price

Test scenarios

The eight cases the engine is exercised against, written the way a loan officer actually types. Each one shows what the model read separately from what it assumed — because an assumed value that looks like a stated one is how a quote ends up wrong in a way nobody catches.

The rules

No model touches these. Every value is config, sourced and dated, and changing one reprices the portfolio without a code change.

Tests

The rules make the decisions, so the rules are what gets tested. Extraction is fuzzy by nature and gets measured with confidence scores instead. The test file is written to read as a specification of the pricing rules.

Build log

Decisions I made, and bugs the first build shipped that I caught by reading output rather than by a test failing. Kept because the failures are more informative than the successes.
